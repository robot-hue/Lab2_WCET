# Лабораторная работа №2 по СРВ

Оценка наихудшего времени выполнения (WCET) фрагмента программы с учетом архитектуры процессора.
Вариант: **«Шаг ПИД-регулятора с фильтрацией входного сигнала»**.

Консольное приложение на Python 3.10+ (разработано на 3.12) с использованием неизменяемых моделей данных (`dataclasses`).

## Что делает программа

- вычисляет лучшее время выполнения операции ($BC_i$) при идеальном кэш-попадании и верном предсказании перехода;
- вычисляет худшее время выполнения операции ($WC_i$) с учетом заложенных штрафов процессора за промахи кэша и сбросы конвейера;
- суммирует по всему фрагменту наилучшее время выполнения (BCET) и наихудшее время выполнения (WCET);
- рассчитывает коэффициент недетерминизма системы как отношение $K_{нд} = WCET / BCET$;
- изолированно анализирует вклад каждого источника задержек (память и ветвления) в тактах процессора;
- по заданному дедлайну определяет, гарантированно ли фрагмент укладывается в жесткие временные ограничения СРВ;
- считывает описание фрагмента кода и параметры процессорной архитектуры из внешнего файла JSON без «магических чисел»;
- выводит детализированную таблицу по операциям и итоговую аналитику в консоль.

## Математический аппарат и формулы

Для каждой отдельной операции $i$ с числом обращений к памяти $m_i$ и числом условных переходов $b_i$ выполняются следующие вычисления:

1. **Лучшее время операции:**
   $$BC_i = c_{base}$$
2. **Худшее время операции:**
   $$WC_i = c_{base} + m_i \cdot p_{cache} + b_i \cdot p_{branch}$$
   *Где $c_{base}$ — базовая стоимость инструкции, $p_{cache}$ — штраф промаха кэша, $p_{branch}$ — штраф ошибки предсказания перехода.*

3. **Общие временные метрики фрагмента:**
   $$BCET = \sum_{i=1}^{n} BC_i, \quad WCET = \sum_{i=1}^{n} WC_i$$

4. **Изолированный вклад источников задержек:**
   $$\Delta_{mem} = \left(\sum_{i=1}^{n} m_i\right) \cdot p_{cache}, \quad \Delta_{branch} = \left(\sum_{i=1}^{n} b_i\right) \cdot p_{branch}$$

## Запуск

```bash
python src/wcet_analyzer.py
```

По умолчанию программа ищет конфигурационный файл по пути `data/pid_config.json`. Также путь к файлу можно передать в качестве аргумента командной строки:
```bash
python src/wcet_analyzer.py data/pid_config.json
```

## Формат входного файла (JSON)

- `base_cost` — стоимость инструкции в тактах при отсутствии задержек процессора;
- `cache_miss_penalty` — штрафной простой конвейера при промахе кэша (такты);
- `branch_mispredict_penalty` — штраф за сброс конвейера при ошибочном предсказании условного перехода (такты);
- `deadline` — максимально допустимый период дискретизации для выполнения данного фрагмента (такты);
- `memory_accesses` — количество обращений к памяти в рамках данной операции;
- `branches` — количество условных переходов в рамках данной операции.

## Структура репозитория

- `data/pid_config.json` — уникальные входные данные (14 операций ПИД-регулятора с фильтром)
- `docs/` — отчет и графические материалы
- `src/wcet_analyzer.py` — исходный код программы анализатора времени
- `.gitignore` — настройки исключений Git (игнорирование pycache)
- `README.md` — описание и документация проекта

## Основные функции (src/wcet_analyzer.py)

- `best_case(op, model)` — расчет идеального времени выполнения инструкции
- `worst_case(op, model)` — расчет максимального времени с учетом штрафов
- `bcet(fragment, model)` — вычисление суммарного наилучшего времени (BCET)
- `wcet(fragment, model)` — вычисление суммарного наихудшего времени (WCET)
- `nondeterminism_ratio(fragment, model)` — вычисление коэффициента недетерминизма
- `source_breakdown(fragment, model)` — раздельный расчет накладных расходов памяти и ветвлений
- `display_results(fragment, model)` — вывод таблицы результатов и проверки дедлайна
- `load_configuration(path)` — безопасное чтение и проверка JSON-файла


## Допущения и особенности

- **Защита от деления на ноль** — в расчете коэффициента недетерминизма предусмотрена проверка на случай нулевой базовой стоимости.
- **Безопасность кодировки** — парсинг файлов конфигурации переведен на стандарт `utf-8-sig` для исключения скрытых ошибок кодировок Windows (BOM).
- **Подсчет штрафов** — при расчете WCET закладывается теоретическое одновременное наступление всех наихудших аппаратных факторов на каждой операции.
